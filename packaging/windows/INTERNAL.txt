MARTLET - INTERNAL DEVELOPMENT ONLY - UNSIGNED

This internal build includes V04b real explicit typed / push-to-talk (PTT) app
integration, V06b local troubleshooting and bundled
Doctor. It is NOT a supported
novice release or a verified live first trial.
There is no microphone capture, playback, provider/key/model lookup, login startup
or network inference on launch.
Do not publish this installer or tell users to bypass SmartScreen/antivirus.
No project code or asset license is granted. Distribution/signing remains gated.

Optional avatar setup is an explicit, separate action. The renderer runs in the
private AvatarRenderer process; its browser shell is bundled offline. Doctor
remains unchanged and does not load avatar, WebView2 or Audio2Face dependencies.
Licensed Live2D Framework/Core overrides, avatar/model assets and the NIM/GPU
runtime are user-supplied prerequisites. The WebView2 runtime, Windows speech,
Ollama and WSL 2/Docker Desktop are installed only when chosen in the Desktop
setup advisor, Thinking or Prerequisites, or in Start > Martlet prerequisites (Internal).
Saving a profile does not establish rendering, model, hardware or inference
readiness. Full bundled dependency notices are retained with this internal build.

Start menu: Martlet (Internal) opens the status shell. Real API
conversation is a separate explicit action; opening it does not start a request.
Martlet Doctor (Internal) opens a command window and prints the same status.
In that window, run Martlet.Doctor.exe --help for the implemented CLI options.
Doctor status can return 2 (incomplete/not ready), which is expected here.

Companion's Thinking, Voice and Listening pages save configuration only:
routes with explicit upstream model/voice IDs and role-specific
destination/data/cost choices. Saving a page makes no provider call and does not
establish account, model or device readiness.
In an authorized real action, microphone audio goes to cloud STT, text to LLM,
and response text to TTS only when generated-voice output is selected.
Screen stays OFF; local memory is separately OFF by default. Key validity,
price and quota are unknown; check the provider's own pricing and data
retention pages. Saved choices never grant capture
on launch or perpetual paid-request permission.

Keys are masked and stored in Windows Credential Manager only when you press a
page's button, for the selected profile, role and provider origin.
Ordinary status never reads a key. Replacement invalidates consent and sets the
old key aside under Keys from before; removing it is separately confirmed.
Interrupted transactions retain pending cleanup metadata: reload and review.
The OS vault does not protect against malware already running as your user.

Real API conversation:
  Save a supported named OpenAI configuration on the Companion pages; return and
  Reload saved choices. Unsupported/missing routes remain unavailable. There
  is no model discovery, automatic fallback, key validation or free-request
  promise. Review the displayed supported IDs, destinations and one-action
  data/cost/output envelope. A saved profile is NOT action permission.
  Typed: enter text, authorize the next action, then Send typed text.
  Typed text does not capture microphone audio; generated voice starts OFF.
  PTT: separately authorize the action, bounded LOCAL microphone capture and
  "separately permit uploading" audio to the named STT destination. Include
  other people's speech only with their permission. STT may incur charges even
  if participation policy suppresses an answer afterward. Hold PTT with mouse
  or Space and release to send; accessible Invoke starts bounded recording,
  then Finish recording and send submits it. No always-on listening.
  Stop / revoke this action discards pending work. Pause, mute, focus loss,
  session lock or closing revoke live work. Cleanup may still own the app slot;
  wait for release rather than starting overlapping work. Provider-side charges
  or speech already heard cannot be undone.
  Retry requires a NEW explicit Send/PTT and fresh consent. Only bounded recent
  completed exchanges can supply volatile context; no earlier audio queue is replayed.
  Microphone/STT failure allows typed
  fallback. Output failure retains response text; refusal remains separate.
Troubleshooting is a separate optional action, never a conversation gate.
This package does not itself prove live API/account/key/model validity,
physical microphone/speaker behavior or consumer first-trial success.

Local memory (OFF by default):
  Open Local memory to review the app-local or custom local scope. Opening it
  does not open the fact store. Enabling needs explicit scope approval.
  Save only facts you explicitly enter, with retention. Inspect/edit/delete
  show exact facts and provenance; delete confirmation defaults No.
  Export requires an exact frozen JSON preview and separate default-No
  permission for one new local file. It never uploads or overwrites.
  Each conversation retrieval needs its own next-action checkbox and shares
  the existing LLM input budget. No automatic transcript ingestion occurs.
  Configuration backup excludes facts and restores memory OFF; installation
  never enables memory or assumes ownership of an existing store.

Troubleshooting (available from the main window, Audio setup
and real conversation, including before a profile exists or with invalid settings):
  Opening Troubleshooting starts no journal, settings write, key lookup, audio
  capture/playback, provider request or upload. Refresh uses shared local checks.
  Record troubleshooting metadata is OFF at every launch. Explicitly enable it
  only when needed; this records bounded metadata, NOT speech or telemetry.
  The selected settings data directory's support-v1 child is the only journal
  scope. It must be a trusted, user-owned local path without network/reparse
  components. Invalid locations fail visibly and are never silently replaced.
  Stop / cancel support work or closing Troubleshooting stops collection.
  Outstanding IO and cleanup must actually finish; retry owned cleanup when
  indicated rather than starting another writer or deleting evidence.
  Engine defaults: 50 MiB, 32 segments, 8 KiB per record, seven-day retention.
  Retention removes whole segments on explicit Start/Append, not an idle timer;
  size/slot pressure can remove newer evidence. Selection is bounded to 2,048
  records / 2 MiB; frozen uncompressed preview is bounded to 4 MiB.
  Select a shared report and optionally an inclusive journal receipt-UTC range.
  Report-only preview does not create/read a journal. Freeze exact preview.
  Preview every frozen file, its size, source and SHA-256: build.json,
  settings.json, doctor.json, events.json and manifest.json. Review provenance
  and omissions; shared reports are not proof of real-mode readiness.
  Choose a separate local ZIP destination with an existing parent. Default-No
  confirmation binds those exact frozen bytes and destination. No existing file
  is overwritten; selection/destination changes require another confirmation.
  Exported locally means a local archive only, not delivery to a maintainer.
  No support contact or upload channel is configured. CLI export is not implemented.
  Do not post an unreviewed bundle publicly. No audio, conversation text, keys,
  screenshots or raw settings are collected; times, counts, versions and
  pseudonymous correlations remain potentially identifying. Exported archives
  are outside journal retention. No universal anonymity/secure erasure promise.
Doctor --help displays the same authored troubleshooting defaults and privacy
bounds through Diagnostics only; Doctor does not bundle Martlet.Support.
See TROUBLESHOOTING.md in this help directory for the full local workflow.

V07a local configuration backup / restore:
  Open from the main window. Opening is passive.
  Configuration snapshots are NOT support bundles, encrypted files or uploads.
  Choose an explicit new local .martlet-config output (create-only), review
  scope, and confirm. Includes validated configuration and personal device IDs;
  excludes secret values, vault, conversation/audio, models and optional logs.
  Restore supports ONLY an existing valid same-profile v1/v2 destination.
  Read exact restore preview, inspect all candidate JSON/changes and source/
  destination revision digests, then confirm (default No). A changed source,
  selection or revision requires a fresh preview.
  Useful route/model/voice/device preferences return INERT: no saved consent,
  live key binding or audio checkpoint is imported. Current owned keys become
  tracked pending cleanup, never automatic deletion. Capture/logging stay OFF.
  A fresh settings.recovery.<uuid>.bak retains exact pre-replacement bytes.
  Stop live work and close/clean up Troubleshooting before recovery. Slow IO/
  cancellation retains ownership past UI timeout/close; reopen to inspect the
  actual result, and retry owned staging cleanup if indicated.
  No portable profile import, corrupt-store repair or executable rollback.
  See TROUBLESHOOTING.md for full scope, errors and preserved evidence.

Doctor examples (no audio, network, settings writes or AI):
  Martlet.Doctor.exe status --json
  Martlet.Doctor.exe run application.version runtime.version --json
Exits: 0 requested checks passed; 1 failure; 2 incomplete/not run;
3 invalid invocation. A pass is NOT real-mode readiness.

Installed program files:
  %LocalAppData%\Programs\Martlet Internal\Desktop\Martlet.Desktop.exe
  %LocalAppData%\Programs\Martlet Internal\Doctor\Martlet.Doctor.exe

Default settings (SEPARATE from program files):
  %LocalAppData%\Martlet\settings.json
Launch reads settings but does not create them. The explicit Create unconfigured
local profile action writes settings; it does not connect a provider.
Setup Save explicitly upgrades v1 settings to v2 with an atomic original-file
snapshot named settings.v1.<opaque-id>.bak in the same data directory.
Malformed/newer settings are reported, not reset.

Repair/reinstall for this internal skeleton:
Close both apps and rerun the SAME installer to replace its owned program files.
Installer-driven migration, transactional upgrade, downgrade or rollback is not
implemented. Setup v1 snapshots and V07a configuration recovery are not lifecycle qualification.
Do not install an older version over newer data as a recovery strategy.

Uninstall through Windows Settings > Apps > Installed apps > Martlet (Internal).
Only installed files and shortcuts are removed. Settings at the separate path
above survive. There is no purge option and no recursive user-data deletion.
The installer does not write, migrate, back up or repair those settings.

If launch fails, retain the exact version, installer SHA-256 and error message.
Do not reset data, elevate, install a runtime, or disable Windows protection to
hide a failure. This self-contained build is expected to carry its own runtime.
Manifest/checksums and upstream notices are included alongside the applications.
Checksums detect corruption; they are not a publisher signature or trust grant.

NOT RUN for this V04b/V06b/V07a integration: real API/account or vault effects, physical
microphone/speaker trials, clean-Windows installation, a live first trial,
signing or release.
Windows 11 25H2 x64 is the target, not a qualified support claim. Clean-machine
install/uninstall/repair, interrupted upgrade, disk-full, novice usability and
signed-download tests still require an isolated Windows VM and release approval.
